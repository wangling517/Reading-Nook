# 多次阅读与选书 Implementation Plan

**Goal:** 书架默认全部；选书按状态和书名搜索；一天多次阅读，计时可纠正，旧数据保留。用户已确认方案并授权执行、发布。

**Architecture:** 每个 day 增加可选 readings 数组，顶层分钟和书籍由每次记录汇总，保持现有云端 JSON 和成长地图兼容。无 readings 的旧日记录按一条历史记录展示，仅在修改时转换。进行中的计时放 IndexedDB meta 的独立 timer 键，按账号和设备保存，不上传、不计入统计；确认保存与清除 timer 在同一事务内完成。

**Tech Stack:** 原有静态 JavaScript、IndexedDB、Supabase、GitHub Pages。沿用现有发布 checkout，直接执行，无额外子代理或基础设施。

- [x] core.js：先增加测试覆盖 15+20+未知=35分钟/1阅读日、历史总量不变、编辑删除与日期迁移、重复提交、无效时间、跨午夜、部分未知汇总和备份验证，再实现领域函数。每次 ID 固定；结束不能早于开始或晚于当前；超过2小时需确认，不能默认认可。
- [x] store.js：计时开始、取消和确认以事务保护；重复开始拒绝；刷新保留；确认失败保留 timer；换号隔离；云端拉取不覆盖本机 timer。测试用原生浏览器 IndexedDB。
- [x] app.js：四个书架状态、全部默认、状态徽标；选书搜索不重建输入框，分类和清空真实可用。首页计时卡、再读一会儿、补记、每日明细、每次编辑删除；切换书籍加入当前计时所读书目。
- [x] reading.css / sw.js / index.html：沿用温暖卡片样式，320—430px检验，无横向溢出；新离线资源与缓存版本一起发布。
- [x] tests：运行 node --test tests/*.test.js 及隔离 Edge 浏览器脚本，覆盖旧记录、备份往返、两设备同步和本机计时不外传；浏览器截图查看首页、搜索和确认弹层。
- 发布步骤（状态以 GitHub Pages 提交及部署检查结果为准）：更新使用说明和验收记录；检查 diff；提交并推送 main；验证 Pages 提交、HTTPS和静态资源；同步回阅读小屋源目录并更新部署包。真实家庭登录未经测试时明确说明。

规则：手填日期/分钟可以不填开始结束；计时自动显示精确到秒的经过时间，保存为整分钟（四舍五入，非零不足一分钟计1分钟）。跨午夜默认按开始日归属，结束字段包含日期。已知时长总和超过当天1440分钟拒绝保存。旧总量是一条“历史阅读记录”，不宣称真实阅读次数。已完成记录正常云同步；计时不跨设备接力。
